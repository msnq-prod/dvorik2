# Подключение Saby Retail

Дата проверки документации: 2026-07-21.

## Принятый контракт

- Сервисная авторизация: `POST https://online.sbis.ru/oauth/service/` с
  `app_client_id`, `app_secret`, `secret_key`; ответ содержит `token`.
- Авторизация Retail API: заголовок `X-SBISAccessToken`.
- Продажи: `GET https://api.sbis.ru/retail/order/list` с `pointId`,
  `fromDateTime`, `toDateTime`, `page`, `pageSize=100`,
  `needDiscountInfo=true`.
- Webhook Saby не имеет опубликованного неизменяемого payload-контракта:
  HTTP-trigger настраивается пользователем. Поэтому Dvorik сохраняет тело для
  диагностики, но использует webhook только как сигнал немедленного polling.

Официальные источники:

- https://saby.ru/help/integration/api/auth/service/
- https://saby.ru/help/integration/api/app_sale/get_sale_data
- https://saby.ru/help/integration/api/app_salon/webhook

## Конфигурация Dvorik

```text
DVORIK_SABY_ENABLED=1
DVORIK_SABY_POINT_ID=<числовой id точки>
DVORIK_SABY_APP_CLIENT_ID=<id приложения>
DVORIK_SABY_APP_SECRET=<защищенный ключ>
DVORIK_SABY_SECRET_KEY=<сервисный ключ>
DVORIK_SABY_WEBHOOK_SECRET=<URL-safe секрет минимум 32 символа>
```

Опционально:

```text
DVORIK_SABY_OVERLAP_MINUTES=30
DVORIK_SABY_INITIAL_LOOKBACK_HOURS=24
```

После сборки API и `npm run worker:saby` должны работать одновременно.
Worker опрашивает Saby каждые 15 минут и немедленно реагирует на новый сигнал.

## Единственное действие в trigger Saby

В «Настройки → Кастомизация → Триггеры» выбрать
«Бизнес/Розница и кассы/Продажи розницы → Изменения информации о продажах»,
действие «Отправить HTTP-запрос» и указать:

```text
https://<публичный-домен>/api/saby/webhook/<DVORIK_SABY_WEBHOOK_SECRET>
```

Отдельная авторизация trigger и конкретные параметры тела не нужны: секрет уже
включён в URL, тело не используется как источник учёта. Путь с секретом
редактируется в production-логах.

## Что обрабатывается

- только завершённые фискальные продажи;
- удаления и переходы в нефискальное состояние компенсируют прежний результат;
- возвраты создают обратную выручку и обратное движение штучного товара;
- изменения количества/цены/скидки применяются дельтой;
- неизвестные UUID не блокируют выручку и попадают в очередь сопоставления;
- весовые товары не меняют остаток по кассовой продаже;
- при активной инвентаризации складская дельта остаётся в очереди;
- повтор окна, webhook или mapping идемпотентен.

## Перед включением

1. Создать сервисное приложение Saby с минимальным правом чтения Retail-продаж
   и, если доступно, ограничить IP адресом Dvorik.
2. Получить ID точки через официальный `/retail/point/list` либо из настроек.
3. Передать секреты только через серверный secret store.
4. Запустить API и worker, убедиться, что `/api/saby/status` показывает успешную
   сверку.
5. Вставить URL trigger и провести одну тестовую фискальную продажу и возврат.

Без реальных ключей, pointId и тестовой продажи нельзя подтвердить тариф,
фактический ответ аккаунта и end-to-end доставку; код не подменяет эту проверку.
