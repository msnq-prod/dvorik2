# Current Admin Map

## App shell

- Навигация хранится локально в `main.tsx` как массив `nav`.
- Активный экран выбирается через локальный `view`, без роутинга.
- Сайдбар содержит 10 плоских кнопок без группировки, ролей и счетчиков.
- Topbar показывает имя текущей вкладки, пользователя, роль, dev/demo auth и переключатель темы.
- Все экраны живут в одном файле `main.tsx`.

## Вкладки и цепочки данных

| Вкладка | Текущий экран | Основные API |
|---|---|---|
| Главная | Метрики и последние движения | `GET /api/summary` |
| Товары | Поиск и карточки товаров | `GET /api/products`, `POST /api/products`, `PATCH /api/products/:id` |
| Склад | Операция движения, остатки, журнал | `GET /api/products`, `GET /api/locations`, `GET /api/balances`, `POST /api/stock/operations` |
| Инвентаризация | Snapshot по локации и корректировки | `GET /api/inventory/:locationId/snapshot`, `POST /api/inventory/apply` |
| Маркировки | Выбор товаров, A4 preview, PDF, журнал | `POST /api/labels/preview`, `POST /api/labels/pdf`, `GET /api/labels/jobs` |
| Импорт | Ручной CSV/base64 ввод, preview, commit, undo | `POST /api/imports/preview`, `POST /api/imports/:id/commit`, `POST /api/imports/:id/undo` |
| Дубли | Preview/commit/undo merge | `POST /api/merges/preview`, `POST /api/merges/:id/commit`, `POST /api/merges/:id/undo` |
| График | Смены, создание, статусы, обмены | `GET/POST/PATCH /api/schedule`, `/api/schedule/swaps` |
| Пользователи | Таблица пользователей | `GET /api/users` |
| Аудит | Backups и журнал аудита | `GET /api/audit`, `GET/POST /api/backups` |

## Общие UX/UI огрехи

- Нет разделения на самостоятельные модули: все экраны и состояния смешаны в одном файле.
- Нет группировки меню по операционным зонам: каталог, склад, документы, персонал, система.
- Нет role-aware навигации: вкладки видны даже если backend потом вернет `403`.
- Нет устойчивых экранных состояний: загрузка, пусто, ошибка, нет прав, успешное действие.
- Формы смешаны с журналами и таблицами без приоритета основного действия.
- Таблицы минимальны: нет сортировки, фильтров, плотности, sticky header, выбора строк.
- Критические действия выглядят как обычные вторичные кнопки.
- Мобильная версия превращает сайдбар в сетку кнопок, но не дает нормального Telegram WebApp паттерна.
- В UI часто видны технические ID, enum и сырые статусы.
- Нет единой модели статусов, бейджей, подтверждений и истории действий.

## Вывод

Текущая версия уже функциональна как прототип, но UI не отражает операционные сценарии магазина. Новый дизайн должен быть не “витриной”, а плотным рабочим инструментом: быстрый доступ к действиям, проверяемые последствия, явные статусы и независимые вкладки.
