# Imports

## Назначение функции

Вкладка нужна для безопасного импорта поставки из CSV/XLS/XLSX: загрузить файл, проверить строки, выбрать локацию прихода, применить импорт, при необходимости откатить созданные товары и приходные операции.

## Что есть сейчас

- Слева форма `Импорт поставки`:
  - имя файла;
  - textarea с CSV или base64 XLS/XLSX;
  - выбор локации прихода;
  - кнопки `Предпросмотр` и `Применить`.
- По умолчанию вставлен пример CSV.
- Справа история импортов: файл, статус, число строк, число созданных товаров.
- Для committed-импортов выводятся отдельные кнопки `Отменить <fileName>`.
- Активный draft хранится в состоянии вкладки; применить можно только текущий preview.
- Сообщения о процессе, успехе и ошибке показываются одним блоком.

## UI controls and data chain

- При открытии вкладки:
  - `GET /api/locations` загружает локации;
  - `GET /api/imports` загружает до 50 импортов, требует `imports:write`.
- `POST /api/imports/preview`:
  - принимает `fileName` и `content`;
  - парсит CSV, base64 XLSX, base64 XLS или HTML/XML table для XLS;
  - требует минимум заголовок и одну строку;
  - считает hash контента;
  - запрещает повтор уже committed-файла;
  - создает draft со статусом `previewed`;
  - пишет audit `supply_import/preview`.
- `POST /api/imports/:id/commit`:
  - требует `imports:write`;
  - требует `idempotency-key`;
  - требует валидную `locationId`;
  - нормализует строки: `name/officialName/название`, `quantity/qty/количество`, `unit/ед`, `localName`, `sku`, `category`;
  - создает новые товары;
  - для строк с количеством больше 0 создает приход на выбранную локацию;
  - переводит import в `committed`;
  - сохраняет `createdProducts`, `receipts`, `productIds`, `operationIds`, `idempotencyKey`;
  - пишет audit `supply_import/commit`.
- `POST /api/imports/:id/undo`:
  - требует `idempotency-key`;
  - откатывает только `committed`;
  - запрещает откат, если по созданным товарам уже были другие движения;
  - удаляет созданные приходные операции, остатки и товары;
  - переводит import в `reverted`;
  - пишет audit `supply_import/undo`.

## UX/UI огрехи относительно сути функции

- Нет настоящего выбора файла; пользователь должен вручную вставлять CSV или base64.
- Предпросмотр не показывает строки, ошибки по строкам, распознанные поля и будущие изменения.
- Локация прихода выбирается до понимания состава файла и не связана с preview.
- Нет явного разделения шагов: загрузка, проверка, маппинг колонок, применение, результат.
- Нельзя настроить маппинг колонок, хотя сервер принимает несколько вариантов названий.
- Нет проверки дублей по SKU/названию до применения; сервер всегда создает новые товары.
- Нет summary до commit: сколько товаров будет создано, сколько приходов, какие строки с нулевым количеством.
- Кнопка `Применить` активируется по наличию draft, но пользователь не видит, какой именно draft будет применен.
- История не показывает дату, локацию, автора, количество приходов, ошибки, id импорта.
- Кнопки отката вынесены отдельно от строк истории; связь с импортом слабая.
- Откат опасный, но нет подтверждения, объяснения последствий и причин, почему откат может быть недоступен.
- Ошибки API показываются общим текстом без привязки к строке или полю.
- Нет состояния загрузки и блокировки повторных кликов при preview/commit/undo.

## Как должно быть реализовано в новом дизайне

- Сделать импорт пошаговым мастером внутри вкладки:
  - `Файл`;
  - `Проверка`;
  - `Маппинг`;
  - `Применение`;
  - `Результат`.
- На первом шаге дать drag-and-drop/file picker для `.csv`, `.xls`, `.xlsx`; textarea оставить только как dev/manual fallback.
- После preview показывать таблицу строк:
  - номер строки;
  - название;
  - SKU;
  - количество;
  - единица;
  - категория;
  - статус валидности;
  - текст ошибки.
- Добавить маппинг колонок на UI-уровне: какая колонка файла идет в `name`, `sku`, `quantity`, `unit`, `category`.
- До commit показывать summary:
  - файл;
  - hash/признак дубля;
  - локация прихода;
  - строк всего;
  - товаров будет создано;
  - приходов будет создано;
  - строк с нулевым количеством;
  - блокирующие ошибки.
- Commit должен быть недоступен при невалидных строках, пустой локации, дубликате committed-файла или отсутствии preview.
- Историю оформить как рабочий журнал:
  - дата;
  - файл;
  - статус;
  - строк;
  - создано товаров;
  - создано приходов;
  - локация;
  - действия `Открыть`, `Откатить`.
- Откат делать через подтверждение с перечислением удаляемых сущностей и понятной причиной недоступности при конфликте.
- Все async-действия должны иметь loading-состояние и защиту от повторного клика.
- При отсутствии права `imports:write` вкладка должна быть скрыта или показывать отказ без формы.

## Самостоятельная вкладка: состав экрана

- Header:
  - название `Импорт`;
  - действие `Новый импорт`;
  - краткие счетчики: previewed, committed, reverted.
- Блок `Новый импорт`:
  - file picker/drag-and-drop;
  - имя файла;
  - ручной ввод CSV/base64 как вторичный режим;
  - кнопка `Проверить файл`.
- Блок `Проверка и маппинг`:
  - выбор соответствия колонок;
  - таблица распознанных строк;
  - ошибки и предупреждения по строкам;
  - summary будущих изменений.
- Блок `Применение`:
  - выбор локации прихода;
  - финальное summary;
  - кнопка `Применить импорт`;
  - результат с количеством созданных товаров и приходов.
- Блок `История импортов`:
  - таблица импортов;
  - фильтр по статусу;
  - раскрытие деталей;
  - действие `Откатить` для доступных committed-импортов.

## Acceptance checklist

- [ ] Пользователь может выбрать файл, а не только вставить содержимое вручную.
- [ ] Preview показывает распознанные строки и ошибки до commit.
- [ ] Есть UI-маппинг колонок для обязательных и опциональных полей.
- [ ] Перед commit видны локация, число строк, создаваемые товары и приходные операции.
- [ ] Commit недоступен без валидного preview и выбранной локации.
- [ ] Повторный committed-файл определяется и блокируется понятным сообщением.
- [ ] Loading-состояния есть для preview, commit и undo.
- [ ] История показывает статус, дату, файл, строки, товары, приходы и действия в строке.
- [ ] Откат требует подтверждения.
- [ ] Откат объясняет конфликт, если после импорта были движения по созданным товарам.
- [ ] Ошибки импорта отображаются рядом с файлом/строкой/действием, а не только общим toast-блоком.
- [ ] UI учитывает право `imports:write`.
