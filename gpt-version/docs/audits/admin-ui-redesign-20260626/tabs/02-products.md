# Products

## Назначение функции

Управлять справочником товаров: находить позиции, проверять идентификаторы, видеть статус, категорию, единицу измерения, фото и пороги остатков.

## Что есть сейчас

- Вкладка называется `Товары`.
- Есть строка поиска и кнопка `Найти`.
- Список товаров отображается сеткой карточек.
- Карточка показывает фото, локальное название, официальное название, категорию, единицу, статус и идентификаторы.
- Создания, редактирования, архивации, удаления, фильтров и пагинации в UI нет.
- API поддерживает больше возможностей, чем вкладка использует.

## UI controls and data chain

- UI: `Products` в `src/client/src/main.tsx`.
- Локальное состояние:
  - `q`: поисковая строка;
  - `products`: текущий список;
  - `message`: текст ошибки/сообщения.
- Первичная загрузка: `GET /api/products?q=&status=all`.
- Поиск:
  - ввод меняет только локальное состояние;
  - запрос выполняется по Enter или кнопке `Найти`.
- API `GET /api/products`:
  - требует `products:read`;
  - параметры: `q`, `status`, `page`, `limit`;
  - ищет по `officialName`, `localName`, `category`, `tags`, `identifiers.value`;
  - возвращает `{ items, total, page, limit }`;
  - для seller скрывает все товары кроме `active`.
- API `POST /api/products`:
  - требует `products:write`;
  - создает товар с `officialName`, `localName`, `unit`, `photoUrl`, `category`, `lowStockThreshold`, `identifiers`;
  - в текущем UI не используется.
- API `PATCH /api/products/:id`:
  - требует `products:write`;
  - обновляет `status`, `localName`, `category`;
  - в текущем UI не используется.

## UX/UI огрехи относительно сути функции

- Справочник выглядит как витрина карточек, а не как рабочая админская таблица.
- Нет быстрого сравнения товаров по SKU/штрихкоду, статусу, категории и порогу остатка.
- Нет фильтра по статусу, хотя UI всегда запрашивает `status=all`.
- Нет пагинации, хотя API возвращает `total`, `page`, `limit`; фактически показываются только первые 20 товаров.
- Нет индикации, что поиск не live: пользователь может изменить строку и видеть старые результаты до Enter/кнопки.
- Нет пустого состояния для `ничего не найдено`.
- Ошибка выводится обычным notice, но старый список может остаться на экране.
- Фото занимает много места и мешает плотной работе со справочником.
- Статусы показываются сырым значением `active/archive/deleted`, без русского текста и смыслового цвета.
- Идентификаторы склеены в одну строку; длинные значения плохо читаются.
- Нет действий по товару: открыть, редактировать, архивировать, удалить, напечатать этикетку, посмотреть остатки.
- Не отображается `lowStockThreshold`, хотя это ключевое поле для складских рисков.

## Как должно быть реализовано в новом дизайне

- Основной вид должен быть таблицей справочника с опциональной миниатюрой, а не карточной сеткой.
- Поиск должен явно показывать примененный запрос или работать live с debounce.
- Нужны фильтры: статус, категория, единица, наличие штрихкода, низкий порог/без порога.
- Нужна пагинация или бесконечная загрузка с отображением `total`.
- Статусы должны быть локализованы и визуально различимы.
- У каждой строки должны быть быстрые действия: открыть детали, редактировать, архивировать, печать этикетки, открыть остатки.
- Детальная панель товара должна показывать все идентификаторы, фото, теги, порог остатка и связанные складские данные.
- Создание и редактирование должны использовать возможности `POST /api/products` и `PATCH /api/products/:id`.
- Для ролей без `products:write` действия записи должны быть скрыты или disabled с понятным объяснением.

## Самостоятельная вкладка: состав экрана

- Верхняя панель:
  - заголовок `Products`;
  - поиск;
  - кнопка `Создать товар` для пользователей с `products:write`;
  - кнопка обновления.
- Фильтры:
  - статус: все, активные, архивные, удаленные;
  - категория;
  - единица измерения;
  - идентификаторы: все, есть штрихкод, нет штрихкода.
- Таблица товаров:
  - миниатюра;
  - локальное название;
  - официальное название;
  - категория;
  - единица;
  - статус;
  - SKU/штрихкод;
  - порог остатка;
  - действия.
- Боковая панель или drawer деталей:
  - полная карточка товара;
  - все идентификаторы;
  - фото;
  - теги;
  - связанные остатки;
  - история последних операций по товару.
- Модалка создания/редактирования:
  - обязательное официальное название;
  - локальное название;
  - категория;
  - единица;
  - фото;
  - порог остатка;
  - список идентификаторов.
- Нижняя зона:
  - пагинация;
  - счетчик `показано N из total`.

## Acceptance checklist

- [ ] Products загружается через `GET /api/products`.
- [ ] Используются `total`, `page`, `limit`; пользователь понимает объем результата.
- [ ] Есть явные состояния загрузки, ошибки и пустого результата.
- [ ] Поиск не оставляет пользователя со старым списком без признака примененного запроса.
- [ ] Есть фильтр по статусу, не только скрытый `status=all`.
- [ ] Основной список пригоден для плотной сверки справочника.
- [ ] Статусы локализованы и визуально различимы.
- [ ] Видны SKU/штрихкод и `lowStockThreshold`.
- [ ] Пользователь с `products:write` может создать и отредактировать товар.
- [ ] Пользователь без `products:write` не видит недоступных write-действий как активные.
- [ ] Есть быстрый переход к остаткам и печати этикеток для выбранного товара.
- [ ] Карточки/фото не мешают массовой работе со справочником.
