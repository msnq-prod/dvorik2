# Склад

## Назначение функции

Проводить складские движения и видеть текущие остатки по товарам и локациям: приход, перемещение, списание, корректировка и журнал операций.

## Что есть сейчас

- Экран состоит из формы `Новая операция` и двух блоков: `Остатки`, `Журнал`.
- Форма поддерживает типы `transfer`, `receipt`, `write_off`.
- Поля формы: тип, товар, источник, назначение, количество, основание.
- После отправки вызывается `POST /api/stock/operations`, затем список данных перезагружается.
- Остатки показываются таблицей: товар, локация, остаток, version.
- Журнал показывает тип операции, количество и причину.
- Отмена операции есть в API, но в UI не подключена.

## UI controls and data chain

- При открытии вкладки загружаются:
  - `GET /api/products?status=all`;
  - `GET /api/locations`;
  - `GET /api/balances`;
  - `GET /api/stock/operations`.
- Проведение движения:
  - форма отправляется в `POST /api/stock/operations`;
  - idempotency key генерируется через `crypto.randomUUID()`;
  - сервер проверяет `stock:move`, товар, локации, количество и запрет отрицательного остатка;
  - результат сохраняется в `db.operations`, меняет `db.balances`, пишет audit.
- Журнал операций берется из последних 100 операций.
- API `POST /api/stock/operations/:id/reverse` существует, но экран его не использует.

## UX/UI огрехи относительно сути функции

- Форма не адаптируется под тип операции: для прихода источник не нужен, для списания назначение не нужно.
- Нет подсказки текущего остатка по выбранному товару и источнику до проведения операции.
- Нет предупреждения о возможном отрицательном остатке до отправки.
- Нет быстрых фильтров по товару, локации, типу операции и периоду.
- Таблица остатков не показывает порог низкого остатка и риск.
- Журнал не показывает дату, автора, товар, источник и назначение.
- В журнале нет действия отмены операции, хотя backend это поддерживает.
- Техническое поле `Version` показано как рабочая колонка без объяснения.
- Нет разделения прав: пользователю без `stock:move` форма должна быть скрыта или read-only.
- Сообщение об ошибке/успехе общее и не привязано к форме.
- Нет защиты от повторного клика во время проведения операции.

## Как должно быть реализовано в новом дизайне

- Разделить экран на `Остатки`, `Новое движение`, `Журнал`.
- Форма движения должна менять поля по типу операции.
- При выборе товара и локации показывать текущий остаток, порог и прогноз после операции.
- Низкие остатки выделять бейджем и цветом.
- Основной список остатков сделать фильтруемой таблицей.
- Журнал операций должен показывать товар, локации, автора, время, тип, количество и причину.
- Отмена операции должна быть доступна только для пользователей с соответствующим правом и через подтверждение.
- Технические версии скрыть в деталях или использовать только для диагностики.
- Все async-действия должны иметь loading и disabled state.

## Самостоятельная вкладка: состав экрана

- Header:
  - название `Склад`;
  - быстрые действия `Приход`, `Перемещение`, `Списание`;
  - кнопка `Обновить`.
- Summary:
  - всего позиций с остатком;
  - низкий остаток;
  - операций за период;
  - последняя операция.
- Таблица `Остатки`:
  - товар;
  - локация;
  - остаток;
  - порог;
  - статус;
  - быстрые действия.
- Drawer/панель `Новое движение`:
  - тип операции;
  - товар;
  - источник/назначение по типу;
  - количество;
  - прогноз остатка;
  - основание.
- Таблица `Журнал операций`:
  - время;
  - тип;
  - товар;
  - откуда;
  - куда;
  - количество;
  - автор;
  - причина;
  - действия.

## Acceptance checklist

- [ ] Данные загружаются из products, locations, balances, operations.
- [ ] Форма меняет обязательные поля по типу операции.
- [ ] Перед отправкой виден текущий остаток и прогноз.
- [ ] Нельзя отправить пустое основание, невалидное количество или одинаковые локации для transfer.
- [ ] Низкие остатки видны в таблице.
- [ ] Журнал показывает дату, товар, автора, источник и назначение.
- [ ] Ошибка отрицательного остатка отображается до или сразу после отправки понятным текстом.
- [ ] Повторный submit блокируется во время запроса.
- [ ] Пользователь без `stock:move` не видит активную форму движения.
- [ ] Действие отмены операции, если добавлено в UI, требует подтверждения.
