# Labels

## Назначение функции

Вкладка нужна для подготовки и повторной печати товарных этикеток: выбрать товары, задать количество и геометрию листа, проверить раскладку, скачать PDF, открыть журнал прошлых заданий.

## Что есть сейчас

- Слева панель параметров: список всех товаров чекбоксами, количество для каждого товара, шаблон, ширина и высота этикетки.
- По умолчанию выбраны `p-1` и `p-2`, количество по 1.
- Есть действия `Предпросмотр`, `Печать`, `Скачать PDF`; последние две кнопки вызывают один и тот же PDF endpoint.
- Справа предпросмотр A4: количество этикеток на странице и сетка этикеток с названием, штрихкодом и датой.
- Ниже журнал печати: таблица последних заданий и отдельные кнопки `Повторить <id>` для первых пяти.
- Сообщения об ошибках и успехе выводятся одним текстовым блоком.

## UI controls and data chain

- При открытии вкладки:
  - `GET /api/products?status=all` загружает товары.
  - `GET /api/labels/jobs` загружает до 50 заданий печати.
- Payload для предпросмотра/PDF:
  - `templateId`
  - `widthMm`
  - `heightMm`
  - `items: [{ productId, quantity }]`
- `POST /api/labels/preview`:
  - проверяет право `labels:print`;
  - валидирует существование товаров;
  - ограничивает количество каждой позиции диапазоном 1-99;
  - считает геометрию A4: `perRow`, `rows`, `labelsPerPage`;
  - возвращает `overflow`, исходные позиции и развернутый список этикеток.
- `POST /api/labels/pdf`:
  - повторяет сборку задания;
  - блокирует PDF, если этикеток больше, чем помещается на страницу;
  - сохраняет задание в `db.labelJobs`;
  - пишет audit `label_job/create`;
  - отдает `dvorik-labels.pdf`.
- `POST /api/labels/jobs/:id/pdf`:
  - ищет сохраненное задание;
  - пишет audit `label_job/reprint`;
  - отдает PDF повторной печати.

## UX/UI огрехи относительно сути функции

- Нет поиска, фильтрации и группировки товаров; при большом каталоге чекбокс-лист становится непригодным.
- Количество доступно даже для невыбранных товаров, из-за этого неясно, какие числа реально попадут в печать.
- Нет явного счетчика выбранных товаров и общего числа этикеток.
- Кнопки `Печать` и `Скачать PDF` дублируют действие.
- Нет состояния загрузки для предпросмотра, генерации PDF и повторной печати.
- Нет предупреждения до предпросмотра, сколько этикеток поместится при текущем размере.
- Ошибки геометрии и overflow показываются поздно, без подсказки, что изменить.
- Предпросмотр визуально не соответствует реальной физической геометрии этикетки: сетка показывает порядок, но не масштаб и поля.
- Шаблон `a4-basic/a4-sku` не объяснен и фактически не влияет на UI-состав этикетки.
- Журнал печати не показывает автора, список товаров, размеры, статус скачивания и причину ошибки.
- Повторная печать оформлена набором кнопок вне строк таблицы; связь с конкретным заданием слабая.
- Нет безопасного сценария массового выбора: выбрать все, снять все, выбрать категорию, задать количество пачкой.

## Как должно быть реализовано в новом дизайне

- Разделить экран на рабочий конструктор и журнал заданий.
- Основной сценарий: `выбор товаров -> настройка формата -> предпросмотр -> скачать/напечатать`.
- Выбор товаров сделать табличным:
  - поиск по названию, SKU, barcode;
  - фильтры по категории/статусу;
  - чекбокс выбора;
  - количество в строке;
  - быстрые действия `выбрать все найденные`, `снять выбор`, `количество всем`.
- Настройки формата вынести в компактный блок:
  - пресеты шаблонов;
  - ширина/высота с min/max;
  - расчет `в ряд`, `рядов`, `на странице`;
  - предупреждение при overflow до генерации PDF.
- Предпросмотр сделать отдельной областью с реалистичной A4-страницей, полями и масштабом.
- Действия назвать по факту:
  - `Обновить предпросмотр`;
  - `Скачать PDF`;
  - `Сохранить и скачать PDF`, если создание job остается серверной стороной.
- Журнал печати оформить таблицей с действиями в строке: дата, автор, шаблон, размер, число этикеток, товары, повторить PDF.
- Сообщения разделить на error/success/info; ошибки должны указывать исправление.
- При отсутствии прав `labels:print` вкладка должна быть скрыта или показывать read-only отказ без рабочих контролов.

## Самостоятельная вкладка: состав экрана

- Header:
  - название `Маркировки`;
  - краткая метрика: выбранных товаров, этикеток всего, помещается на страницу;
  - основное действие `Скачать PDF`.
- Левая колонка `Товары для печати`:
  - поиск;
  - фильтры;
  - таблица товаров с чекбоксом, названием, SKU/barcode, категорией, единицей, количеством;
  - bulk actions.
- Правая колонка `Формат этикетки`:
  - пресет шаблона;
  - ширина/высота;
  - расчет сетки;
  - статус вместимости.
- Центральная/нижняя область `Предпросмотр`:
  - A4-лист;
  - сетка этикеток;
  - состояние `нет предпросмотра`, `загрузка`, `overflow`, `готово`.
- Нижний блок `Журнал печати`:
  - таблица последних заданий;
  - действие `Повторить PDF` в строке;
  - раскрытие состава задания.

## Acceptance checklist

- [ ] Вкладка загружает товары и журнал печати без блокировки основного UI.
- [ ] Есть поиск и фильтрация товаров.
- [ ] Количество редактируется только для выбранных товаров или явно показывает неактивное состояние.
- [ ] Видны счетчики выбранных товаров, общего числа этикеток и вместимости страницы.
- [ ] Предпросмотр показывает overflow до скачивания PDF.
- [ ] Нельзя скачать PDF при пустом выборе, невалидной геометрии или overflow.
- [ ] Ошибки API отображаются рядом с релевантным действием.
- [ ] `Печать` и `Скачать PDF` не дублируют один и тот же смысл без различий.
- [ ] Журнал показывает дату, шаблон, размер, количество этикеток и действие повторной печати.
- [ ] Повторная печать не теряет исходную геометрию и состав задания.
- [ ] Экран пригоден при большом количестве товаров.
- [ ] UI учитывает право `labels:print`.
