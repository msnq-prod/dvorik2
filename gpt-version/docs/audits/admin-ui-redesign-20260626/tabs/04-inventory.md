# Инвентаризация

## Назначение функции

Провести сверку фактических остатков по выбранной локации, увидеть расхождения и применить корректировки с audit trail.

## Что есть сейчас

- Вкладка содержит выбор локации и кнопку `Загрузить snapshot`.
- После загрузки snapshot показывается список строк по товарам.
- В каждой строке есть товар, учетное количество, поле факта и дельта.
- По умолчанию `actual = expected`, `delta = 0`.
- Есть поле комментария и кнопка `Подтвердить корректировки`.
- После применения вызывается `POST /api/inventory/apply`, затем snapshot перезагружается.

## UI controls and data chain

- При открытии:
  - `GET /api/locations`;
  - `GET /api/products?status=all`.
- Snapshot:
  - `GET /api/inventory/:locationId/snapshot`;
  - backend требует `inventory:write`;
  - возвращает строки `productId`, `locationId`, `expected`, `version`.
- Ввод факта:
  - UI хранит `actual` и `delta`;
  - `delta` пересчитывается на клиенте.
- Применение:
  - `POST /api/inventory/apply`;
  - body: `rows`, `comment`;
  - idempotency key через `crypto.randomUUID()`;
  - backend валидирует actual, version и создает операции `inventory_adjustment`.

## UX/UI огрехи относительно сути функции

- Нет отдельного статуса сессии инвентаризации: начата, заполнена, есть расхождения, применена.
- Нет поиска и фильтрации строк по товару, категории, дельте.
- Нет быстрого ввода только расхождений.
- Нет сканирования штрихкода или быстрого поиска товара по SKU.
- Дельта показана, но нет цветового/смыслового объяснения положительного и отрицательного расхождения.
- Нет итогов: сколько строк проверено, сколько расхождений, суммарный плюс/минус.
- Нет защиты от ухода со страницы с несохраненными изменениями.
- Нет подтверждения перед применением корректировок.
- Нет детализации созданных операций после применения.
- Нет read-only режима для пользователя без `inventory:write`.
- Ошибки версии/конфликта не показывают, какие строки устарели.
- Snapshot нужно загружать вручную, но пустое состояние не объясняет следующий шаг.

## Как должно быть реализовано в новом дизайне

- Сделать процесс инвентаризации пошаговым: выбрать локацию, загрузить snapshot, ввести факт, проверить расхождения, применить.
- Основной список должен быть таблицей с поиском, фильтрами и быстрым вводом факта.
- Должны быть summary-показатели: всего строк, проверено, расхождений, плюс, минус.
- Строки с дельтой выделять статусом: совпадает, недостача, излишек.
- Перед применением показывать confirm с числом корректировок и комментарием.
- После применения показывать результат: созданные операции и ссылка на складский журнал.
- При конфликте версий показывать конкретные строки, которые надо обновить.
- При пустом snapshot показать понятный empty state.

## Самостоятельная вкладка: состав экрана

- Header:
  - название `Инвентаризация`;
  - выбранная локация;
  - статус текущей проверки;
  - кнопка `Обновить snapshot`.
- Панель запуска:
  - выбор локации;
  - кнопка `Начать проверку`;
  - подсказка по последнему snapshot.
- Summary:
  - строк всего;
  - заполнено;
  - без расхождений;
  - недостача;
  - излишек.
- Таблица проверки:
  - товар;
  - SKU/barcode;
  - учет;
  - факт;
  - дельта;
  - статус;
  - заметка строки, если API будет расширен.
- Нижняя панель:
  - комментарий;
  - `Показать только расхождения`;
  - `Сбросить факт к учету`;
  - `Применить корректировки`.
- Результат:
  - список созданных операций;
  - переход в `Склад -> Журнал`.

## Acceptance checklist

- [ ] Snapshot загружается по выбранной локации.
- [ ] Есть понятное empty state до загрузки snapshot.
- [ ] Таблица показывает товар, учет, факт, дельту и статус.
- [ ] Есть поиск или фильтр по товару.
- [ ] Есть фильтр `только расхождения`.
- [ ] Summary показывает количество проверенных строк и расхождений.
- [ ] Положительная и отрицательная дельта визуально различаются.
- [ ] Нельзя применить без комментария и без snapshot.
- [ ] Перед применением есть confirm.
- [ ] Ошибка конфликта версии показывает проблемные строки.
- [ ] После применения показан результат и данные обновлены.
- [ ] Пользователь без `inventory:write` не видит активные controls применения.
