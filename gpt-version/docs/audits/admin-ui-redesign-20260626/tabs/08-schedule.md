# Schedule

## Назначение функции

Вкладка нужна для управления графиком смен и заявками на обмен сменами. Администратор создает, редактирует, копирует и отслеживает смены. Сотрудник видит свои смены и может предложить обмен запланированной смены другому активному сотруднику.

## Что есть сейчас

- Экран состоит из двух колонок: слева создание смены и обмен, справа список смен и заявки.
- Форма "Новая смена" доступна только при `schedule:manage`.
- Поля смены: дата, начало, конец, точка, статус, сотрудники, комментарий.
- Смена создается кнопкой "Создать смену".
- Блок "Обмен смены" доступен всем авторизованным пользователям.
- Список смен фильтруется локально по режиму "Неделя" или "Месяц" и `focusDate`.
- Карточка смены показывает дату, время, комментарий и список `employeeIds`.
- Администратор может менять только статус смены и копировать смену на дату из формы создания.
- Заявки на обмен выводятся таблицей и набором кнопок под таблицей.
- Для pending-заявок получатель может принять/отклонить, инициатор может отменить.

## UI controls and data chain

- `GET /api/schedule` возвращает все смены для `schedule:manage`; иначе только смены текущего пользователя.
- `POST /api/schedule` создает смену; требует `schedule:manage`.
- `PATCH /api/schedule/:id` обновляет смену; требует `schedule:manage`.
- `POST /api/schedule/:id/copy` копирует смену на дату из body; требует `schedule:manage`.
- `GET /api/staff` возвращает активных сотрудников.
- `GET /api/locations` возвращает точки.
- `GET /api/schedule/swaps` возвращает все заявки для `schedule:manage`; иначе только заявки, где пользователь инициатор или получатель.
- `POST /api/schedule/swaps` создает заявку обмена: только для своей смены, только если смена `scheduled`, получатель должен быть активным и не равным текущему пользователю.
- `POST /api/schedule/swaps/:id/accept` заменяет `fromUserId` на `toUserId` в `employeeIds`, ставит заявку в `accepted`.
- `POST /api/schedule/swaps/:id/decline` ставит `declined`.
- `POST /api/schedule/swaps/:id/cancel` ставит `cancelled`.
- `refreshScheduleState` автоматически переводит смены в `in_progress` и `completed` по времени Владивостока; pending-заявки становятся `expired`, если исходная смена больше не `scheduled`.
- Сервер проверяет формат даты, формат времени, активность сотрудников, активность локации, пересечение смен у сотрудников и обязательность хотя бы одного сотрудника.

## UX/UI огрехи относительно сути функции

- Нет календарной сетки: режим недели/месяца остается набором карточек без дней, занятости и пустых слотов.
- Карточка смены показывает `employeeIds`, а не имена сотрудников.
- Точка смены в карточке не отображается.
- Редактирование неполное: нельзя изменить дату, время, точку, сотрудников и комментарий существующей смены.
- Копирование использует дату из формы новой смены, что неочевидно и легко приводит к ошибке.
- Нет подсветки конфликтов до отправки формы; пересечения видны только как серверная ошибка.
- Статусы можно выбрать вручную без пояснения автоматических переходов.
- Обмен смены показывает все смены из локального списка, но сервер разрешит только собственные `scheduled` смены.
- Заявки не связаны визуально со сменами: в таблице нет даты, времени, точки и имен сотрудников.
- Кнопки заявок расположены отдельно от строк таблицы; непонятно, к какой заявке относится действие без чтения id.
- Нет отдельных состояний для сотрудника и администратора; один экран смешивает планирование, личный обмен и журнал заявок.

## Как должно быть реализовано в новом дизайне

- Сделать основным представлением календарь смен, а не список карточек.
- Для недели показывать дни и смены внутри дня; для месяца показывать плотность и ключевые смены с переходом в день.
- В карточке смены показывать время, точку, имена сотрудников, статус и комментарий.
- Для администратора дать полноценный drawer/modal редактирования смены: дата, время, точка, сотрудники, статус, комментарий.
- Создание смены должно сразу показывать проверку обязательных полей и потенциальных пересечений.
- Копирование смены должно открывать явный выбор новой даты, а не брать дату из другой формы.
- Статусы отображать как жизненный цикл: draft, scheduled, in_progress, completed, cancelled.
- Автоматические статусы объяснять в деталях смены: расчет идет по Asia/Vladivostok.
- Для сотрудника блок обмена должен показывать только свои доступные `scheduled` смены.
- Заявки на обмен должны быть строками с inline-действиями и контекстом смены: дата, время, от кого, кому, статус.
- Для администратора добавить обзор всех заявок и фильтры по статусам.
- После любого действия экран должен перезагружать смены и заявки либо обновлять затронутые элементы.

## Самостоятельная вкладка: состав экрана

- Верхняя панель:
  - переключатель "Неделя / Месяц";
  - выбор даты;
  - фильтры по точке, сотруднику и статусу;
  - кнопка "Создать смену" для `schedule:manage`.
- Основная зона:
  - календарная сетка;
  - карточки смен с временем, точкой, сотрудниками и статусом;
  - пустые состояния для дней без смен.
- Боковая панель/модалка смены:
  - просмотр деталей;
  - редактирование для администратора;
  - копирование с выбором даты;
  - история или системная пометка об автостатусе.
- Блок "Мои обмены":
  - доступные смены для обмена;
  - выбор получателя;
  - список моих входящих и исходящих заявок.
- Блок "Все заявки" для администратора:
  - таблица с датой смены, инициатором, получателем, статусом;
  - фильтры;
  - без действий, если текущий пользователь не участник заявки.
- Общая зона сообщений: ошибки валидации, результат создания, обновления, копирования и обмена.

## Acceptance checklist

- [ ] Администратор видит все смены, сотрудник видит только свои.
- [ ] Создание смены недоступно без `schedule:manage`.
- [ ] В смене отображаются имена сотрудников, точка, время, дата, статус и комментарий.
- [ ] Нельзя создать смену без активного сотрудника.
- [ ] Нельзя создать или обновить смену с пересечением по сотруднику.
- [ ] Нельзя создать смену с окончанием раньше или равным началу.
- [ ] Копирование смены требует явного выбора новой даты.
- [ ] Редактирование смены покрывает все поля модели `Shift`.
- [ ] Режим недели показывает календарную неделю относительно выбранной даты.
- [ ] Режим месяца показывает смены выбранного месяца.
- [ ] Обмен можно создать только для своей `scheduled` смены.
- [ ] Получатель обмена не может быть текущим пользователем.
- [ ] Pending-заявки имеют inline-действия в своей строке.
- [ ] Принять/отклонить может только получатель.
- [ ] Отменить может только инициатор.
- [ ] Expired-заявки отображаются без доступных действий.
- [ ] После действий со сменами и заявками данные на экране обновляются.
- [ ] Автоматические переходы `scheduled -> in_progress -> completed` учитываются в UI.
