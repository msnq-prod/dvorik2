# Dashboard

## Назначение функции

Дать администратору быстрый операционный срез: ассортимент, складские риски, текущая смена, уведомления и последние движения товара.

## Что есть сейчас

- Вкладка называется `Главная`.
- Показываются 4 метрики: активные товары, низкий остаток, сейчас на смене, уведомления.
- Ниже показан список последних 6 складских операций.
- Данных по самим товарам, локациям, сотрудникам и уведомлениям в интерфейсе нет: только числа и короткий журнал.
- Нет фильтров, переходов в проблемные места, статусов загрузки по блокам, ручного обновления.

## UI controls and data chain

- UI: `Dashboard` в `src/client/src/main.tsx`.
- Загрузка: один запрос `GET /api/summary` при монтировании вкладки.
- Ответ API:
  - `activeProducts`: число активных товаров, для seller скрываются неактивные товары.
  - `lowStock`: число складских балансов, где `quantity <= product.lowStockThreshold`.
  - `currentShiftEmployees`: число сотрудников в сменах со статусом `in_progress` на сегодня по `Asia/Vladivostok`.
  - `latestOperations`: последние 6 записей из `db.operations`.
  - `notifications`: последние 5 уведомлений текущего пользователя или все для не-seller.
- Перед расчетом summary сервер вызывает `refreshScheduleState()`, поэтому открытие dashboard может менять статусы смен.
- Компоненты отображения: `Metric`, `OperationList`, `Skeleton`.

## UX/UI огрехи относительно сути функции

- Метрика `Низкий остаток` не объясняет, какие товары и где требуют действия.
- Считаются строки балансов, а не уникальные товары; одно и то же наименование в нескольких локациях может завышать тревогу.
- `Уведомления` показываются только числом, без списка, типа, срочности и отметки прочтения.
- `Последние движения` не показывает товар, локации, автора и время; видны только тип, количество и причина.
- Нет явного CTA для складских рисков: пополнить, переместить, списать, открыть склад.
- Нет состояния ошибки: ошибка запроса подавляется, пользователь видит вечный skeleton.
- Нет ручного обновления и времени последней синхронизации.
- На мобильном все метрики идут одной колонкой без приоритизации; самый важный риск не выделен.

## Как должно быть реализовано в новом дизайне

- Dashboard должен быть рабочей панелью исключений, а не набором счетчиков.
- Главный акцент: что требует действия сейчас: низкий остаток, активная смена, свежие операции, непрочитанные уведомления.
- Каждая метрика должна иметь расшифровку и переход в связанную вкладку с примененным фильтром.
- Низкий остаток должен показывать топ проблемных позиций: товар, локация, остаток, порог, рекомендуемое действие.
- Журнал движений должен быть читаемым: время, товар, тип, количество, откуда/куда, автор, причина.
- Уведомления должны быть списком с типом, текстом, временем и состоянием прочтения.
- Ошибка загрузки должна быть видимой; нужна кнопка `Обновить`.
- Данные должны обновляться явно или по короткому polling-интервалу, но без скрытых побочных эффектов в UI.

## Самостоятельная вкладка: состав экрана

- Верхняя строка:
  - заголовок `Dashboard`;
  - время последнего обновления;
  - кнопка `Обновить`.
- KPI-полоса:
  - активные товары;
  - товары/балансы ниже порога;
  - сотрудники на смене;
  - непрочитанные уведомления.
- Блок `Требует внимания`:
  - список низких остатков;
  - быстрые действия: открыть склад, создать приход, создать перемещение.
- Блок `Смена сейчас`:
  - сотрудники;
  - локация;
  - начало/конец смены;
  - статус.
- Блок `Последние движения`:
  - таблица или плотный список последних операций;
  - ссылки на товар и складскую операцию.
- Блок `Уведомления`:
  - последние уведомления;
  - фильтр `все / непрочитанные`;
  - действие `отметить прочитанным`, если API это поддержит.

## Acceptance checklist

- [ ] Dashboard загружается из `GET /api/summary`.
- [ ] Есть явное состояние загрузки, ошибки и пустых данных.
- [ ] Есть кнопка ручного обновления.
- [ ] Метрики имеют подписи, единицы смысла и переходы в связанные вкладки.
- [ ] Низкий остаток раскрывается до товара, локации, остатка и порога.
- [ ] Последние движения показывают товар, тип, количество, время, автора и локации.
- [ ] Уведомления отображаются списком, а не только счетчиком.
- [ ] Самый критичный блок виден без прокрутки на desktop и mobile.
- [ ] Dashboard не смешивает dev-контролы авторизации с рабочими действиями.
- [ ] Ошибка API не превращается в бесконечный skeleton.
