# Merge

## Назначение функции

Вкладка нужна для безопасного объединения дублей товаров: выбрать товар-источник, выбрать итоговый товар, увидеть последствия, применить merge и при необходимости откатить его до появления новых движений.

## Что есть сейчас

- Экран состоит из двух панелей: форма "Объединение дублей" и "История merge".
- В форме есть два селекта товаров: "Источник" и "Итоговый товар".
- Кнопка "Предпросмотр" создает запись merge со статусом `previewed`.
- Кнопка "Объединить" активна только для текущего `previewed` merge.
- История показывает `ID`, `Статус`, `Источник`, `Цель`.
- Для `committed` merge выводятся отдельные кнопки "Отменить {id}".
- Названия товаров в истории не раскрываются: видны только технические id.
- Предпросмотр не показывает фактические изменения по остаткам, идентификаторам, статусу источника и движениям.

## UI controls and data chain

- `GET /api/products?status=all` загружает товары для выбора источника и цели.
- `GET /api/merges` загружает последние 50 merge-операций.
- `POST /api/merges/preview` принимает `sourceProductId`, `targetProductId`; требует `merge:write`; создает `ProductMerge` со snapshot исходного и итогового товара, остатков и операций.
- `POST /api/merges/:id/commit` применяет merge; переносит identifiers источника в цель, суммирует остатки по локациям, переводит операции источника на цель, помечает источник как `deleted`.
- `POST /api/merges/:id/undo` откатывает только `committed` merge; блокируется, если после merge появились новые движения или журнал движений изменился.
- Тип `ProductMerge`: `previewed | committed | reverted`, `sourceProductId`, `targetProductId`, `snapshot.source`, `snapshot.target`, `snapshot.balances`, `snapshot.operations`, `createdAt`, `committedAt`.
- Серверные ошибки: одинаковые товары, отсутствие товара, недостаток прав, неверное состояние merge, конфликт отката.

## UX/UI огрехи относительно сути функции

- Нет поиска по товарам; селекты неудобны при большом каталоге.
- Не видно, какой товар будет удален, а какой останется.
- Нет сравнения карточек source/target: названия, артикулы, штрихкоды, категории, единицы, фото, статусы.
- Нет preview последствий: какие остатки сложатся, какие локации затронуты, сколько операций будет перепривязано.
- Критическое действие "Объединить" не требует явного подтверждения.
- История не читается без знания id.
- Откат показан как набор кнопок без статуса доступности и без объяснения, почему откат может быть заблокирован.
- После commit/undo локальная история не обновляется полноценно: обновляется текущий merge, но строка в списке может остаться со старым статусом до перезагрузки.
- Сообщения об ошибках не привязаны к конкретному полю или действию.

## Как должно быть реализовано в новом дизайне

- Сделать вкладку рабочим инструментом сверки дублей, а не простой POST-формой.
- Выбор товаров через searchable combobox с показом имени, id, артикула/штрихкода, категории и статуса.
- Source и target показывать двумя соседними карточками с явной маркировкой: "будет удален" и "останется итоговым".
- Перед commit показывать diff:
  - переносимые identifiers;
  - остатки source, target и итог по каждой локации;
  - количество операций, которые будут перепривязаны;
  - статус source после merge: `deleted`.
- Кнопка commit должна быть доступна только после успешного preview и подтверждения выбранной пары.
- Для опасного commit нужен confirm step с текстом выбранной пары.
- История должна показывать человекочитаемые названия товаров, время создания, время применения, статус и доступность отката.
- Undo должен быть отдельным действием строки с предупреждением о возможном конфликте движений.
- После commit/undo список должен синхронизироваться с сервером или точечно обновлять измененную строку.

## Самостоятельная вкладка: состав экрана

- Верхняя зона: заголовок "Объединение дублей", краткий статус прав и последняя операция.
- Левая колонка: поиск и выбор source.
- Правая колонка: поиск и выбор target.
- Центральный блок preview:
  - сравнение карточек товаров;
  - таблица остатков по локациям;
  - список переносимых identifiers;
  - счетчик затронутых операций.
- Нижняя action bar:
  - "Сформировать preview";
  - "Объединить";
  - "Сбросить выбор".
- Блок истории:
  - фильтры по статусу;
  - строки merge с названиями source/target;
  - действия "Открыть детали", "Откатить" для `committed`.
- Детали merge: snapshot source/target, balances, operations count, ошибки отката.

## Acceptance checklist

- [ ] Нельзя выбрать один и тот же товар как source и target.
- [ ] Source и target визуально различаются по смыслу: source удаляется, target остается.
- [ ] Перед commit виден diff по identifiers, остаткам и операциям.
- [ ] Commit невозможен без актуального preview.
- [ ] Commit требует явного подтверждения.
- [ ] История показывает названия товаров, а не только id.
- [ ] Статусы `previewed`, `committed`, `reverted` отображаются понятно.
- [ ] Undo доступен только для `committed`.
- [ ] При конфликте undo пользователь видит причину: новые движения или изменение журнала.
- [ ] После preview/commit/undo UI обновляет текущий merge и историю.
- [ ] Ошибки API отображаются рядом с действием, которое их вызвало.
- [ ] Экран остается usable без знания технических id.
