# UX/UI модель Dvorik WebApp

Дата: 2026-06-29.
Целевая поверхность: Telegram WebApp для телефона, с dev/test режимом для локальной проверки.

## Суть приложения

Dvorik WebApp - рабочий мобильный интерфейс для продавца и администратора точки. Его основная задача - быстро ответить на операционные вопросы во время смены:

- где лежит товар и сколько его осталось;
- что нужно переместить, списать или отправить в зал;
- когда у продавца смена и есть ли заявки на обмен;
- как проверить фактический остаток;
- как быстро собрать маркировки;
- для администратора - как управлять поставками, дублями, пользователями, аудитом и расписанием.

Это не CRM и не аналитическая панель. На телефоне приложение должно быть рабочим инструментом, а не уменьшенной админкой.

## Главный UX принцип

Сначала действие, потом детали. Пользователь открывает экран не для чтения описаний, а чтобы выполнить конкретный сценарий. Поэтому экран должен отвечать на один основной вопрос:

- `Меню`: куда мне сейчас пойти?
- `Товары`: есть ли товар и где он?
- `Склад`: что есть в точке и что с этим сделать?
- `График`: когда смены и есть ли обмены?
- `Проверка`: что посчитать и какие расхождения применить?
- `Маркировки`: какие этикетки напечатать?
- admin-only страницы: что требует решения и какая основная операция доступна?

## Роли

### Продавец

Продавцу нужны только рабочие сценарии смены. Интерфейс продавца должен:

- не показывать служебные метрики без прямого действия;
- не дублировать имя пользователя, роль и очевидные заголовки;
- не показывать журналы, статусы и админские сущности;
- использовать короткие названия: `Наличие`, `Поиск`, `График`, `Проверка`;
- давать быстрый доступ к складу и расписанию;
- показывать товар через карточку с остатками по локациям;
- вести перемещение товара явным маршрутом `откуда -> куда -> количество -> действие`.

### Администратор

Администратор может видеть больше данных, но мобильный экран все равно должен быть task-first. Для админа допустимы метрики и таблицы, если они помогают принять решение, но они не должны вытеснять основную операцию из первого экрана.

## Навигация

На телефоне нужна стабильная нижняя навигация:

- `Меню`;
- `Товары`;
- `Склад`;
- `График`;
- `Еще`.

`Еще` открывает drawer с редкими разделами. Drawer не должен дублировать текущий экран как основной способ работы, а должен быть вторичной навигацией.

Кнопка назад в topbar должна вести на `Меню`, если это основной раздел, а внутри сложных сценариев лучше использовать локальное действие `Скрыть`, `Все точки`, `Назад к списку`.

## Визуальная иерархия

На каждом экране:

- topbar содержит один короткий заголовок;
- второй такой же H1 внутри страницы не нужен;
- первичное действие одно и визуально сильнее остальных;
- вторичные действия серые или контурные;
- карточки не вложены в карточки без необходимости;
- метрики используются только там, где пользователь реально принимает решение по числу;
- пустое состояние объясняет следующий шаг, а не просто сообщает, что данных нет.

## Мобильная эргономика

Требования для 360-390 px ширины:

- основные действия доступны большим пальцем;
- кликабельные цели не меньше 44 px по высоте;
- bottom-nav не перекрывает последний важный блок;
- все формы помещаются без горизонтального скролла;
- таблицы превращаются в карточки с понятными подписями;
- длинные названия товаров, SKU и штрихкоды переносятся без наложений;
- disabled-кнопки визуально отличаются от активных;
- поиск и фильтр не должны занимать больше места, чем результат.

## Язык интерфейса

Текст должен быть коротким и рабочим:

- `Остатки` или `Наличие`, а не `Проверить остаток - найти товар или локацию`;
- `В зал`, `Переместить`, `Списать`, `Загрузить`, `Применить`;
- без англоязычных терминов в пользовательском UI, если есть русский эквивалент: `штрихкод` вместо `barcode`, `артикул` вместо `SKU`, если это не официальный термин клиента;
- без технических ролей и сущностей на продавце;
- без повторов в заголовке и первом блоке.

## Целевая структура страниц

| Страница | Цель | Идеальный первый экран |
|---|---|---|
| Меню продавца | Быстрый вход в рабочие сценарии | 2x2 плитки: наличие, поиск, график, проверка |
| Товары продавца | Найти товар и остатки | Поиск + карточки товаров с остатками по точкам |
| Склад продавца | Работать с остатками по локациям | Поиск/локация + плитки локаций или список товаров |
| Карточка товара склада | Выполнить действие с товаром | Остатки по локациям + маршрут перемещения + количество |
| График | Смотреть месяц и обмены | Календарь месяца; предложения обмена появляются только когда есть |
| Проверка | Сверить факт с учетом | Точка + загрузить + список товаров после загрузки |
| Маркировки | Собрать PDF этикеток | Список товаров с количеством + формат + предпросмотр/PDF |
| Меню администратора | Войти в операционные разделы | Быстрые действия + сгруппированные разделы без лишнего повторения |
| Товары admin | Управлять каталогом | Поиск/создание товара; метрики вторичны |
| Склад admin | Контролировать остатки и движения | Локации/операция; журнал и нулевые остатки ниже по приоритету |
| Импорт | Проверить и применить поставку | Новый импорт + статус последней проверки |
| Дубли | Проверить и объединить товары | Пара товаров + последствия до применения |
| Пользователи | Управлять доступами | Поиск сотрудников + статус/роль; права роли ниже |
| Аудит | Проверить журнал и копии | Журнал действий + создание копии; метрики не должны съедать экран |

## Доступность

Минимальный целевой уровень:

- видимый focus/selected state у интерактивных элементов;
- текст в кнопках и карточках не меньше читаемого мобильного размера;
- календарные chips читаются без приближения;
- чекбокс кликается вместе с подписью;
- элементы формы имеют понятные labels;
- состояние после действия сообщается через заметный feedback;
- цвет не является единственным носителем статуса.

## Что считать хорошим итогом

Хорошее приложение выглядит спокойно и утилитарно. Оно не пытается быть лендингом, не показывает пользователю лишнюю внутреннюю бухгалтерию и не заставляет искать действие среди повторяющихся заголовков, метрик и таблиц.

Для продавца хороший экран должен работать за 5-10 секунд: открыл, нашел, нажал, ушел.
