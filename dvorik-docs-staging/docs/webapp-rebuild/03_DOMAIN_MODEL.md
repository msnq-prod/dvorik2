# Доменная модель и инварианты

## 1. Основные сущности

### User

- `id` — внутренний ID.
- `telegram_user_id` — уникальная Telegram identity.
- `first_name`, `last_name`, `username`.
- `status`: pending, active, blocked, rejected, archived.
- `role_id`.

### Role и Permission

- Базовые роли: seller, admin, super_admin.
- Роль содержит набор permissions.
- Проверка прав выполняется backend для каждого command/query.
- UI-скрытие кнопки не считается защитой.

### AuthSession

- Привязана к пользователю.
- Имеет срок действия, способ входа и `revoked_at`.
- Все сессии отзываются после блокировки или критического изменения прав.

### Product

- Внутренний ID является единственной идентичностью.
- `official_name`, `local_name`, `unit`.
- `photo_id`.
- `status`: active, archived, deleted.
- Может иметь категории, теги, штрихкоды и несколько артикулов.

### ProductIdentifier

- `product_id`.
- `type`: supplier_article, barcode, legacy_article, other.
- `value`.
- `supplier_id` для артикула поставщика.
- Уникальность определяется комбинацией типа, значения и контекста, а не только строкой артикула.

### Supplier

- Отдельная сущность.
- Используется в поставках и правилах сопоставления.
- Не равен производителю.

Производитель отдельной обязательной сущностью не является. Если данные понадобятся для отображения, они могут храниться как атрибут товара.

### Location

- Внутренний ID и стабильный code.
- `type`: warehouse, house, counter, other.
- `parent_id` для иерархии.
- `status`: active, archived.
- `HALL` не хранится как локация остатка.

### StockBalance

- Пара `product_id + location_id`.
- `quantity` — decimal.
- `version` — для optimistic concurrency.
- `quantity >= 0`.

### StockOperation

- Неизменяемая запись о движении.
- Типы: receipt, transfer, write_off, inventory_adjustment, correction, reversal, merge.
- Содержит источник, назначение, количество, автора и идемпотентный ключ.
- Отмена создаёт новую операцию.

### InventoryDraft

- Краткоживущий ввод фактического количества.
- Нужен для защиты от конфликтов даже без отдельного пользовательского понятия «сессия».
- Хранит snapshot version остатка.

### SupplyImport

- Статусы: uploaded, mapping_required, reviewing, ready, committing, committed, failed, reverted.
- Содержит hash файла и idempotency key.
- Содержит строки импорта и решения сопоставления.

### ProductMerge

- Статусы: previewed, committed, reverted.
- Хранит snapshot обеих карточек и итоговое решение.

### ScheduleAssignment

- Дата, сотрудник, источник изменения.
- Должна исключать дубли назначения.

### ShiftSwapRequest

- pending → accepted | declined | cancelled | expired.
- После accepted назначения меняются атомарно.

### Notification

- Канал: telegram, webapp.
- Тип, payload, состояние доставки и прочтения.

## 2. Критические инварианты

1. Остаток никогда не отрицательный.
2. Любое изменение остатка создаёт `StockOperation`.
3. Повтор команды с тем же idempotency key не меняет данные повторно.
4. Перемещение списывает и зачисляет в одной транзакции.
5. Списание в зал не создаёт остаток `HALL`.
6. Артикул не определяет товар без контекста.
7. Поставка либо применяется полностью, либо не применяется.
8. Объединение товара либо переносит все связанные данные, либо откатывается полностью.
9. Удаление товара мягкое; физическое удаление не используется в обычном UI.
10. Изменение роли немедленно влияет на backend-проверки и отзывает сессии.
11. Принятый обмен сменами меняет оба назначения в одной транзакции.
12. Журнал операций не редактируется и не удаляется через UI.

## 3. Permission matrix, начальная версия

| Возможность | Seller | Admin | Super admin |
|---|---:|---:|---:|
| Просмотр активных товаров | Да | Да | Да |
| Изменение локального имени/фото | Да | Да | Да |
| Перемещение и списание | Да | Да | Да |
| Инвентаризация | Да | Да | Да |
| Просмотр отчётов | По permission | Да | Да |
| Импорт/откат поставок | Нет | По permission | Да |
| Объединение дублей | Нет | По permission | Да |
| Управление расписанием | Нет | По permission | Да |
| Обмен своей сменой | Да | Да | Да |
| Управление пользователями | Нет | По permission | Да |
| Изменение ролей/permissions | Нет | Нет | Да |
| Технический журнал | Нет | По permission | Да |

Матрица должна стать машинно-читаемым контрактом до реализации API.

## 4. Источники истины

- Товар: таблица/aggregate `Product`, не строки поставки.
- Остаток: `StockBalance`, подтверждённый журналом `StockOperation`.
- Права: backend permission service.
- Статус поставки: `SupplyImport`.
- Статус обмена: `ShiftSwapRequest`.
- Состояние UI не является источником бизнес-истины.
