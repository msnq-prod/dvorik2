# Открытые решения

AI-агент не должен самостоятельно закрывать эти вопросы.

## P0 — блокируют архитектуру

### D-001. Стек нового приложения

Нужно выбрать frontend, backend, ORM и способ миграций.

### D-002. Авторизация standalone browser

Подтверждено: без пароля, токен выдаётся через бота. Нужно определить TTL, одноразовость, привязку к устройству и отзыв.

Рекомендация: одноразовый token на 5 минут → HttpOnly session cookie.

### D-003. Откат поставки после последующих движений

Требование подтверждено, но текущая balance-модель не позволяет безопасный полный откат.

Нужно выбрать:

1. Учёт партий/provenance.
2. Компенсирующий алгоритм с анализом цепочки.
3. Изменить продуктовое требование.

### D-004. Модель блокировки инвентаризации

Отдельная пользовательская сессия не нужна, но конфликтующие изменения должны блокироваться.

Нужно выбрать pessimistic lock локации или optimistic versions.

## P1 — блокируют конкретные модули

### D-005. Состав маркировки

Владелец исключил старый обязательный набор полей, но новый набор не определён.

Нужно определить доступные поля, defaults и нужен ли вообще QR/barcode.

### D-006. Что означает MVP для поставок и печати

Обе функции нужны для полной замены, но должны быть переработаны. Нужно определить, входят ли они в первый эксплуатационный релиз или в следующий этап.

### D-007. Критические подтверждения

Ответ на вопрос Q135 отсутствует. Нужно перечислить действия, требующие confirm:

- списание;
- инвентаризационная корректировка;
- откат;
- merge;
- удаление;
- изменение роли.

### D-008. Пользовательские настройки уведомлений

Пользователь не меняет частоту самостоятельно. Нужно определить, кто и где задаёт режимы.

### D-009. Производитель

Отдельная сущность не нужна, но старые данные и UI используют производителя. Нужно решить: удалить, хранить текстовым атрибутом или заменить брендом.

### D-010. Перенос реальных данных

Перенос всей истории не нужен, но MVP требует реальные данные. Нужно перечислить таблицы и минимальную дату среза.

## P2 — можно решить позже

### D-011. Формат развёртывания

Собственный сервер подтверждён, Docker Compose отклонён. Нужен конкретный process manager/reverse proxy/backup procedure.

### D-012. Порог низкого остатка

Персональный порог товара не нужен. Нужно подтвердить единый порог и единицы.

### D-013. Время ежедневной сводки

Нужно зафиксировать timezone и время.

### D-014. Светлая тема

Поддержка подтверждена. Нужен единый design token contract для Telegram theme и standalone theme.
