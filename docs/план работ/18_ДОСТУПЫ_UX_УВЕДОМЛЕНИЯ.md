# B09. Доступы, UX и уведомления

## Фактический статус — 2026-07-21

Доступная часть B09 реализована: роли `seller/admin/super_admin`, Telegram
onboarding, блокировка и отзыв сессий, backend permissions, мобильный seller UX,
SQLite outbox и уведомления stock threshold/zero, обменов и активной
инвентаризации. Негативными HTTP-тестами подтверждено отсутствие финансовых
маршрутов для seller/admin. Seller-flow проверен в браузере на 390 px.

Magic link, daily scheduler и события Saby/поставок не реализованы: они не входят
в утверждённый независимый scope и зависят от post-launch либо внешних контуров.

## Результат блока

Каждая роль получает понятный рабочий интерфейс без лишних данных, а критические
события доставляются через надёжный outbox с проверяемыми правилами.

## Границы

В текущей независимой реализации включены роли, onboarding, Telegram WebApp,
responsive UX, notification catalog, instant preferences и технический аудит.

## Цели

1. Исключить доступ продавца и администратора к закрытым финансам.
2. Сделать основные операции удобными на мобильном устройстве.
3. Унифицировать WebApp, API и Telegram вокруг общих services.
4. Не терять уведомления при сбое Telegram.
5. Не создавать уведомления, прямо исключённые scope.

## План работ

### 1. Матрица доступа

- Продавец: Telegram WebApp, склад, разрешённые операции, инвентаризация и общий
  календарь.
- Администратор: каталог, полки, поставки, aliases, merge, Saby mappings,
  график и технические ошибки.
- Владелец: все функции, назначение администраторов, зарплата, налоги, расходы,
  выручка, прибыль и reopen периода.
- Каждое permission проверяется backend-ом.

### 2. Identity

- Новый сотрудник запрашивает доступ через Telegram.
- Администратор или владелец подтверждает продавца; администратора назначает
  только владелец.
- Блокировка немедленно отзывает все сессии.
- Desktop magic link одноразовый и выдаётся через Telegram.
- Секрет токена не попадает в URL-логи после обмена на HttpOnly session.

### 3. UX продавца

- Главный экран с разрешёнными быстрыми действиями.
- Camera scan и fallback поиска по названию.
- Крупные touch targets, состояния loading/success/error/conflict.
- Инвентаризация без черновика и лишних финансовых данных.
- Общий календарь и обмен сменами.
- Проверка Telegram theme, 390 px и tablet.

### 4. UX администратора и владельца

- Desktop navigation по рабочим контурам.
- Очереди действий: Saby mappings, поставки без цены, import conflicts,
  критический отрицательный остаток и sync errors.
- Owner finance area физически скрыта и закрыта API для других ролей.
- Preview перед массовыми и компенсирующими действиями.

### 5. Уведомления

- Напоминания об активной инвентаризации до завершения.
- Ошибки Saby — администратору.
- Несопоставленные позиции — одной сводкой администратору.
- Отрицательный остаток после отката — администратору и владельцу.
- События обмена — сотрудникам по подтверждённым правилам.
- Ежедневная сводка владельца с настройкой состава, времени и timezone.
- Общие настройки уведомлений доступны администратору и владельцу в пределах их
  полномочий.
- Уведомление «остатка меньше N дней» не реализуется.

### 6. Надёжность и аудит

- Уведомление создаётся в outbox внутри бизнес-транзакции.
- Worker использует lease, retry/backoff, max attempts, DLQ и manual retry.
- Telegram failure не отменяет business operation.
- Технический аудит хранится бессрочно.
- Пользовательского экспорта аудита нет.

## Средства

- permission middleware и negative route tests;
- hardened sessions/magic links;
- existing responsive React shell;
- camera/browser device tests;
- event catalog и SQLite outbox worker;
- accessibility and visual checks;
- Telegram fixtures.

## Артефакты

- final permission matrix;
- role-specific navigation map;
- onboarding/magic-link contract;
- notification catalog;
- seller/admin/owner E2E suite;
- accessibility report;
- outbox operations runbook.

## Критерии приёмки

- Продавец не получает admin, purchase, revenue, payroll или profit данные через
  UI и прямой API-вызов.
- Администратор не получает зарплаты, налоги и прибыль.
- Только владелец назначает/снимает администратора.
- Блокировка пользователя делает существующую сессию недействительной сразу.
- Magic link одноразовый и не может быть повторно использован.
- Основные seller flows проходят на 390 px и реальной камере.
- Каждая mutation показывает понятные success/error/conflict states.
- Ошибка Telegram переводит сообщение в retry, не теряя событие.
- Несопоставленные позиции приходят одной сводкой.
- Ежедневная сводка использует настройку владельца и business timezone.
- Запрещённое уведомление о запасе в днях отсутствует.
- Технический аудит доступен только разрешённой роли и не экспортируется.
