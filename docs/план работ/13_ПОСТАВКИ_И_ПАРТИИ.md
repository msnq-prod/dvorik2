# B04. Поставки, партии, импорт и дубли

## Результат блока

Администратор загружает реальную накладную, разрешает неоднозначности и одной
атомарной командой создаёт поставку, партии, товары и остатки с полным
происхождением и FIFO.

## Границы

Включены `.xlsx`, `.xls`, `.csv`, preview/commit, supplier templates, партии,
закупочная цена, доставка, FIFO, aliases, duplicate candidates, merge, undo и
откат поставки. AI и внешняя обработка накладных запрещены.

## Цели

1. Сделать импорт измеримо широким, но конечным и проверяемым.
2. Не допускать частично применённых поставок.
3. Сохранить происхождение каждой строки, партии и операции.
4. Обеспечить корректный пересчёт себестоимости при поздней цене и merge.

## План работ

### 1. Ingestion и безопасность

- Проверять расширение, MIME, размер и hash.
- Блокировать повторно применённый файл.
- Обрабатывать все листы, включая скрытые.
- Извлекать несколько таблиц и вычисленные значения формул.
- Не исполнять макросы и не передавать файл внешним сервисам.

### 2. Распознавание структуры

- Определять таблицы, заголовки, итоговые и служебные строки.
- Извлекать название, производителя, артикул, количество, единицу, упаковку и
  массу.
- Поддерживать число коробок и количество единиц в коробке.
- Показывать причины исключения строк.
- Дать ручное выделение таблицы и сопоставление колонок в любой момент.

### 3. Preview и resolution

- Редактирование распознанных строк.
- Создание производителя из поля.
- Восстановление исключённых строк и удаление пустых.
- Выбор группы с порогом 80%, процентом и двумя-тремя причинами.
- Блокировка всей поставки при любой нерешённой строке.
- Сохранение supplier template только с проверкой структуры следующего файла.

### 4. Commit поставки

- Один файл — одна поставка, поставщик и дата.
- Закупочная цена вводится за штуку или коробку с явной конверсией.
- Весовая закупочная цена вводится за пачку с массой в граммах.
- Цена может отсутствовать; отчёты помечаются неполными, dashboard напоминает.
- Доставка хранится одной суммой поставки и не распределяется по товарам.
- Новые товары создаются только из подтверждённого preview.
- Commit создаёт receipt, lots, placements, audit и outbox одной транзакцией.

### 5. FIFO и перерасчёт

- Каждое расходное событие получает FIFO allocations.
- Поздняя закупочная цена пересчитывает открытые периоды.
- Закрытый период меняется только после reopen владельцем.
- Финансовая неполнота сохраняется, пока есть использованные партии без цены.

### 6. Дубли и aliases

- Автоматическое объединение только по проверенному alias.
- Проверенный alias подтверждает только администратор; каждое автоматическое
  объединение создаёт уведомление с быстрым undo.
- Кандидаты используют название, перестановку слов, артикул, barcode,
  производителя и aliases.
- Разные производители не объединяются.
- Одинаковый barcode у разных производителей является конфликтом.
- Preview показывает остатки, партии, продажи, identifiers и конфликтующие поля.
- Главной остаётся более старая карточка.
- Merge и undo сохраняют provenance операций до и после merge.
- При undo старые операции возвращаются исходной карточке, а новые поставки,
  созданные после merge, остаются у главного товара.

### 7. Откат поставки

- Только компенсирующая операция.
- Preview показывает зависимые движения и будущий остаток.
- Отрицательный остаток требует отдельного подтверждения.
- После подтверждения создаются критическое предупреждение и задача ручного
  восстановления.

## Средства

- локальные spreadsheet parsers;
- fixture-driven parser tests;
- hash/idempotency registry;
- supplier templates с structural fingerprint;
- transaction/UoW B02;
- FIFO allocation service;
- provenance ledger;
- preview UI и server-side validation.

## Артефакты

- import contract и parser pipeline;
- fixture catalog с ожидаемыми строками;
- preview/resolution/commit UI;
- lots/FIFO services;
- duplicate/merge specification;
- supply rollback workflow;
- audit и recalculation evidence.

## Критерии приёмки

- Каждый предоставленный файл даёт утверждённый preview.
- Скрытые листы и несколько таблиц не теряются.
- Формула импортируется только при наличии валидного вычисленного значения.
- Нераспознанная структура переводится в manual mapping без потери файла.
- Одна ошибочная строка блокирует весь commit.
- Повтор файла или commit не удваивает остаток.
- Commit полностью откатывается при внутренней ошибке.
- Поставка без цены допустима и видна как финансово неполная.
- FIFO потребляет старейшие доступные партии.
- Поздняя цена детерминированно пересчитывает разрешённые периоды.
- Merge/undo сохраняет исходные операции и новые post-merge поставки по
  подтверждённым правилам provenance.
- Откат с отрицательным остатком невозможен без отдельного подтверждения.
- Файлы не отправляются во внешние сервисы.
