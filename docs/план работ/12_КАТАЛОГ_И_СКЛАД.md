# B03. Каталог и склад

## Результат блока

Администратор управляет каталогом и полками, а продавец безопасно выполняет
разрешённые складские операции с пачками и штучными товарами.

## Границы

Включены каталог, группы, цены, производители, barcode, общий остаток,
размещения и ручные складские операции. Поставки, Saby-продажи и закрытие
инвентаризации реализуются в следующих блоках.

## Цели

1. Представить фактический ассортимент без неоднозначных единиц.
2. Разделить учётный остаток и оперативную карту полок.
3. Исключить запрещённые ручные продажи штучных товаров.
4. Обеспечить быстрый мобильный сценарий сканирования.

## План работ

### 1. Товарные группы и цены

- Создать группу «Сладости» для мармелада, орехов и маршмеллоу с ценой за кг.
- Создать штучные группы, включая леденцы, упакованный мармелад, воду, соки и
  чаи.
- Добавить обязательный тип группы: весовая или штучная.
- Хранить историю групповой цены без изменения старых операций.
- Для кофе сохранить отдельную категорию без складского учёта ингредиентов.

### 2. Карточка товара

- Название Dvorik как главное.
- Производитель из управляемого списка и подтверждённые aliases.
- Артикул строкой с ведущими нулями.
- Barcode и внешние идентификаторы.
- Для весового товара обязательная масса пачки в граммах.
- Разные массы пачки создают разные товары.
- Архивация без физического удаления истории.

### 3. Полки

- Создание и архивация только администратором.
- Поддержка нескольких полок одного товара.
- Выключение полок с общей локацией «Склад».
- После включения — список поступившего во время отключения товара для
  распределения.
- Размещение показывается как оперативная подсказка, а не отдельный склад.

### 4. Операции продавца

- Поиск и сканирование barcode.
- Перемещение между полками без изменения общего остатка.
- Перенос одной целой пачки весового товара в зал без выбора количества.
- Ручное перемещение целых единиц штучного товара.
- Комментарий к обычному перемещению необязателен.
- Регистрация брака любым продавцом с необязательным комментарием.
- Запрет ручного продажного списания штучного товара.

### 5. Отмена и отрицательные пути

- Отмена операций только администратором.
- Отмена оформляется компенсацией, история не переписывается.
- Обычные операции отклоняются при недостаточном остатке.
- Дробная пачка и дробная штука отклоняются.
- Повторный scan/submit не создаёт вторую операцию.

- admin UI групп, товаров и полок;
- seller scan/move flow;
- history/reversal view;
- domain, API и E2E tests;
- операция/роль/уведомление matrix.

## Критерии приёмки

- Весовой товар нельзя сохранить без положительной массы пачки.
- Штучный товар нельзя изменить на дробное количество.
- Старые операции сохраняют прежнюю цену группы.
- Один товар может отображаться на нескольких полках.
- Выключение полок не меняет общий остаток.
- Перемещение между полками не меняет общий остаток.
- Один scan весового товара переносит ровно одну пачку в зал.
- Продавец не может выполнить ручную продажу штучного товара через UI или API.
- Брак доступен продавцу и не требует комментария.
- Обычное перемещение не требует комментария.
- Недостаточный остаток даёт стабильную бизнес-ошибку без частичного изменения.
- Отмена доступна администратору и создаёт отдельную compensating operation.
- Основные сценарии проходят на 390 px без горизонтального скролла.
