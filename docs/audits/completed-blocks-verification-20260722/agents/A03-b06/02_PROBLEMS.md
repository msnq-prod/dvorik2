# A03 — B06: подтверждённые проблемы

## P1 — нет ночной полной сверки и отчёта о расхождениях

План B06 требует ночную полную сверку согласованного периода и отображение расхождений (`docs/план работ/15_SABY_И_ПРОДАЖИ.md:31-37,76-77`). Реальный worker выполняет только cursor/overlap sync раз в 15 минут или после сигнала (`gpt-version/src/server/saby-worker.ts:20-39`). Сервис создаёт запись запуска, но не хранит и не вычисляет расхождения (`saby-sync-service.ts:42-76`; схема `012_saby_sales.sql:98-108`). Отдельного nightly scheduler/report в коде не найдено.

Следствие: пропущенный переход вне overlap-окна не будет обнаружен гарантированно.

## P1 — возврат сверх принятого количества не предупреждается

План требует сохранить такой возврат с предупреждением (`15_SABY_И_ПРОДАЖИ.md:48-51`). `ReturnSaleKey` только сохраняется в `saby_sales` (`012_saby_sales.sql:51-67`, `saby-sync-service.ts:141-146`), но не участвует в расчёте. Для возврата `applyLine` увеличивает остаток, если итог неотрицателен (`saby-sync-service.ts:156-177`); alert создаётся лишь для unknown mapping/negative stock (`:177`).

Следствие: возврат без исходной продажи или больше исходной тихо увеличит остаток. В текущем тесте возврат намеренно выполняется после удалённой исходной продажи и проверяется только рост остатка (`saby-sync-service.test.ts:50-58`), предупреждение не проверяется.

## P2 — raw polling response не является durable inbox с trace ID

План требует сохранять raw response в durable inbox с техническим trace ID (`15_SABY_И_ПРОДАЖИ.md:31-37`). Есть raw webhook-signal (`012_saby_sales.sql:9-20`) и `raw_json` только в успешно нормализованной записи продажи (`012_saby_sales.sql:51-67`, `saby-sync-service.ts:139-146`). При ошибке нормализации order вызывает исключение до записи сырого ответа (`saby-sync-service.ts:55-58,67-75`). Для polling payload нет inbox-таблицы или trace ID.

Следствие: проблемный фактический ответ нельзя воспроизвести из БД; диагностика реального контрактного отклонения ограничена логами.
