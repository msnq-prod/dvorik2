# A02 — проверка B05/B07

## Граница

Проверены отметки B05 и B07 в `docs/план работ/99_PROGRESS.md:33-37` против полного плана B05/B07, серверного кода, HTTP-маршрутов и профильных тестов. Код продукта не менялся.

## B05: подтверждено

- Одна активная сессия, только активные весовые товары и снимок общего остатка: `gpt-version/src/server/inventory-session-service.ts:47-59`.
- Создатель сессии является единственным, кто может её закрыть; дробные пачки и неполная форма отклоняются: `inventory-session-service.ts:63-83`.
- Закрытие пишет общий остаток, total-only операцию и один `consumption_records` при недостаче; всё выполняется в UoW: `inventory-session-service.ts:85-100`.
- Ручной расход/корректировка и складские операции блокируются активной сессией: `inventory-session-service.ts:112-135`, `stock-operation-service.ts:149-159`.
- Повтор команды идемпотентен, параллельные сценарии покрыты. Пройдены `inventory-session-service`, `inventory-session-concurrency`, `inventory-reversal-concurrency`, `inventory-reminder-service` tests.
- Saby-линия во время сессии сохраняется со статусом `queued_inventory`: `saby-sync-service.ts:156-176`; последующая попытка есть в worker: `saby-worker.ts:27-32`.

## B07: подтверждено

- Профили сотрудников и нефинансовые HR-события (отпуск, больничный, опоздание, невыход, неполная смена) доступны только с `staff:manage` и аудируются: `staff-schedule-service.ts:43-74`.
- Реализован взаимный обмен именно двумя сменами; конфликты собираются как предупреждения, не блокируют обмен: `staff-schedule-service.ts:77-100`.
- Повтор accept идемпотентен, принятый обмен отменяет только `schedule:manage`, уведомления отправляются всем активным сотрудникам: `staff-schedule-service.ts:104-145,164-171`; проверено в `staff-schedule-service.test.ts:51-71`.
- Пройдены `staff-schedule-service`, `staff-schedule-concurrency`, `schedule-swap-service`, `schedule-swap-concurrency` tests.

## Итог статуса

Отметки подтверждают только узкий фактически реализованный срез, прямо описанный в `99_PROGRESS.md`. Полные блоки из `14_ИНВЕНТАРИЗАЦИЯ_И_РАСХОД.md` и `16_РАСПИСАНИЕ_И_ЗАРПЛАТА.md` не завершены; их нельзя считать закрытыми по исходным критериям приёмки.
