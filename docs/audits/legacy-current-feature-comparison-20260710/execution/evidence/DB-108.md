# DB-108 evidence

Дата: 2026-07-15.

## Результат

- `buildNormalizedStateSql` больше не запускается при каждом save: он остаётся
  только bootstrap converter для пустой normalized SQLite.
- Production stock/reverse/inventory используют один SQLite UoW с balance,
  operation, audit, notification/outbox и idempotency.
- Production schedule/day/swaps, product create/update, media audit и
  notification preferences пишут точечно в SQLite; AppState не перезаписывает
  эти изменения.

## Проверка

- `npm run check` — pass.
- `NODE_ENV=test npx tsx src/server/state-migration.test.ts` — pass.
- `NODE_ENV=test npx tsx src/server/stock-operation-service.test.ts` — pass.
- `NODE_ENV=test npx tsx src/server/inventory-reversal-service.test.ts` — pass.
- `NODE_ENV=test npx tsx src/server/schedule-swap-service.test.ts` — pass.
- `NODE_ENV=test npx tsx src/server/session-http.test.ts` — pass.
- `npm run build` — pass.

## Negative / two-process

- stock replay/reversal/inventory, schedule/day и product create/update
  выполняются в двух API-процессах;
- normalized rows видны второму процессу;
- `app_state.payload` остаётся неизменным после SQL command paths;
- converter regression сохраняет migration-only поведение.

## Остаточный риск

`AppState` всё ещё загружается для dev compatibility и remaining secondary
routes. Его production removal и rg gate — `DB-109`.
