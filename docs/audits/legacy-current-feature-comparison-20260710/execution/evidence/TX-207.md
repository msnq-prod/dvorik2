# TX-207 evidence

Дата: 2026-07-15.

## Результат

- SQLite identity service атомарно меняет user/status/primary role, отзывает
  sessions, пишет audit и target outbox.
- Production Telegram webhook использует только SQLite hooks: onboarding не
  открывает `AppState` transaction и не меняет compatibility projection.
- Role permissions читаются из role tables; last super admin, self-block и
  self-demotion запрещены.

## Изменения

- `gpt-version/src/server/telegram.ts` — SQLite-only production webhook path.
- `gpt-version/src/server/session-http.test.ts` — two-process Telegram
  request/approve/replay, audit/outbox и unchanged `app_state` regression.

## Проверка

- `npm run check` — pass.
- `NODE_ENV=test npx tsx src/server/identity-service.test.ts` — pass.
- `NODE_ENV=test npx tsx src/server/session-http.test.ts` — pass.
- `npm run build` — pass.

## Негативные сценарии

- replay onboarding callback не создаёт второй audit/outbox;
- callback выполняется из второго API process;
- production webhook не записывает stale identity data в `app_state`;
- identity service проверяет unauthorized role change, last super admin,
  self-block/self-demotion и rollback audit/outbox faults.

## Остаточный риск

SQLite outbox dispatch/lease/retry — следующий `EPIC-P3`; legacy AppState
остаётся в других production routes до `EPIC-P2`.
