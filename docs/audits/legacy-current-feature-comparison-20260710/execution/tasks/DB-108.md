# DB-108 — Remove full-state projection from saves

## Статус

- `done`; P0; dependencies `DB-107`, `TX-203..209`.

## Цель

Production mutation path не выполняет `DELETE + INSERT` normalized tables через
`buildNormalizedStateSql`. Stock/inventory/schedule writes используют SQLite
UoW с audit/idempotency/outbox в одной транзакции.

## Evidence criteria

- одна stock operation меняет только balance/operation/audit/outbox/idempotency;
- fault rollback сохраняет все связанные таблицы;
- два API-процесса немедленно видят результат без AppState overwrite;
- accepted routes не вызывают `saveState`/`stateTransaction`.

## Текущий checkpoint

- Production stock operation, reversal и inventory уже используют
  `StockOperationService`/`InventoryService`/`ReversalService` с SQLite UoW.
- Schedule/day/swap mutation и swap read path переведены на
  `ScheduleSwapService`/SQL query adapter; AppState не меняется в two-process
  smoke.
- До закрытия остаются product/media и прочие legacy mutation paths, после чего
  full-state projection будет запрещён в production.

## Выполнение

- Evidence: `../evidence/DB-108.md`.
- `buildNormalizedStateSql` запускается только для bootstrap пустой SQLite;
  release-critical command paths не вызывают full-state projection.
- Следующий ID: `DB-109`.
