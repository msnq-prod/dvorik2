# Карточки задач

Одна карточка — один проверяемый контракт. Перед работой агент сверяет реестр, зависимости, исходный план и текущее состояние кода. После реализации он заполняет отдельный `evidence/<ID>.md`, меняет статус в реестре и только затем берёт следующую карточку. Нельзя расширять scope молча, отмечать `done` по одному typecheck или заменять production-решение fallback-заглушкой.

Для крупной итерации главный агент выдаёт независимые карточки субагентам, оставляя у себя архитектурный контракт, конфликтующие файлы, интеграцию и общий release gate.

## Материализация карточек

Готовые карточки созданы для первого рабочего контура: `DOC-001..003`,
`SEC-000..002`, `FIX-501..508`, `DB-101..106`. Остальные строки реестра имеют
`Card: —` и создаются ведущей моделью перед открытием соответствующей итерации.

Ведущая модель копирует `TEMPLATE.md`, переносит только один ID из полного плана,
добавляет актуальные symbols/files после read-only проверки и проводит review
карточки до передачи простой модели. Простая модель не должна одновременно
проектировать отсутствующую карточку и реализовывать production-код.

Карточка не дублирует весь roadmap: она содержит локальный context budget,
входные gates, разрешённые файлы, конкретный контракт и evidence. Изменение
целевого поведения сначала вносится в `03_DECISIONS.md`/полный план, затем в card.
