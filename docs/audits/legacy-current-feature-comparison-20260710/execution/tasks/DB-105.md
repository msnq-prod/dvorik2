# DB-105 — Repository contracts

- Статус: `pending`; P0; зависит от DB-104.
- Контуры: users/sessions/roles, catalog/supplier, stock, schedule, workflows,
  notifications/outbox/audit/idempotency.

## Шаги
1. Определить domain-oriented interfaces и query/command separation.
2. Сохранить external IDs/API, не экспортировать SQL row names.
3. Все methods получают transaction context/clock/pagination явно.
4. JSON payloads versioned; nullable semantics documented.

## DoD
Application service можно тестировать с fake repository; PostgreSQL adapter не
требует изменения service contract; interfaces review принят до mappers.

## Contract checkpoint 2026-07-12

- Public/API user shape сохраняет one primary role; multiple role assignments не выбираются тихо mapper-ом.
- Repository record содержит opaque revision; update принимает expected revision и explicit UTC clock.
- Not found возвращает `undefined`; nullable storage semantics остаются в mapper.
- JSON/document payload передаётся только как `{ schemaVersion, value }`.
- List/query принимает bounded cursor page; deterministic ID tie-breaker обязателен.
- Interfaces sync для текущего `better-sqlite3` UoW; domain names/types не зависят от SQLite.
- Missing notification persistence, shift time/version, lease/DLQ, entity revisions и schema fields — не silent fallback;
  они остаются follow-up `DB-106`, `MIG-402`, `TX-*`, `OUT-*`.
