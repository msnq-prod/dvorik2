# DB-109 — Remove production AppState

## Статус

- `done`; P0; dependencies `DB-108`, `TX-201..209`.

## Цель

Production API и workers не импортируют global `db`, `saveState` или
`stateTransaction`; `app_state.payload` остаётся только migration tooling/tests.

## Evidence criteria

- `rg '\\bdb\\.' src/server` не находит production application code;
- API и worker сразу видят SQLite changes друг друга;
- startup не читает/не меняет compatibility payload.

## Текущий checkpoint

- Production `store` больше не вызывает `loadState()`; index не очищает legacy
  sessions и не меняет `app_state` при startup. Two-process regression
  подтверждает legacy-token rejection при unchanged payload.
- Accepted: production entrypoint and active workers are isolated from legacy
  AppState; source gate, two-process webhook and SQLite outbox gates pass.
- Label create/list/reprint переведены на `label_jobs`; two-process PDF/job
  regression подтверждает unchanged `app_state`.
- Pure SQL-report PDF rendering вынесен из legacy report module; production
  entrypoint может использовать renderer без `AppState` dependency.
- Production entrypoint больше не имеет static import `store`, `domain`,
  `reports` или `telegram`: legacy bundle загружается только вне production;
  Telegram production onboarding вынесен в SQLite-only handler. Two-process
  webhook gate остаётся зелёным.
- `auth`/barcode больше не тянут legacy domain transitively; disabled daily
  worker не открывает `store`. Targeted import scan пустой.
