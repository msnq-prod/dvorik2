# Исполняемый индекс

Этот каталог — короткий рабочий контекст для агента. Полные требования находятся в `../94_FULL_COMPLETION_PLAN.md`; этот набор не заменяет их.

## Порядок чтения на каждом запуске

1. `01_AGENT_RULES.md`.
2. `04_PROGRESS.md` — определить `Next`.
3. `06_PRODUCTION_ACCELERATION_PLAN.md` — release-critical scope и текущий epic.
4. `05_AUTONOMOUS_COMPLETION_PLAN.md` — полный post-launch DoD и правила сходимости.
5. Карточку `tasks/<ID>.md`, если она существует; иначе раздел `<ID>` в `../94_FULL_COMPLETION_PLAN.md`.
6. Только относящиеся к задаче разделы `02_CURRENT_STATE.md` и `03_DECISIONS.md`.
7. `handoffs/LATEST.md`, текущий `git status` и diff.
8. Код и тесты всего затрагиваемого контура: UI → API → service/domain → persistence/worker.

## Порядок выполнения

`DOC-001..003` → `SEC-001`, `SEC-000` → независимые `FIX-501..504` →
`DB-101..106` → `TX-201..209` вместе с зависимыми `SEC-002`,
`FIX-505/506/508` → `OUT-301..309`, `SEC-303..308`, `FIX-507` →
`DB-107..109`/migration → продуктовые блоки → test/release/rollback.

Зависимости внутри каждого ID из плана обязательны. Более поздний ID нельзя использовать для обхода незавершённого P0.

## Один рабочий цикл

1. Выбрать только `Next` или один явно разрешённый тесный кластер.
2. Сверить требование с фактическим кодом; не доверять старому статусу.
3. Записать краткий план и критерии evidence.
4. Реализовать вертикальный срез и негативные пути.
5. Выполнить focused tests; на границе блока — `npm run check`, `npm run test`, `npm run build` и требуемый integration/E2E.
6. Обновить `04_PROGRESS.md`, `handoffs/LATEST.md` и `evidence/<ID>.md`.

## Stop gates

- Нет карточки/evidence-критериев для выбранного ID — сначала создать их.
- Не выполнена зависимость ID — не начинать реализацию.
- Неясен production contract, владелец, SLO/RPO/RTO или необратимое бизнес-решение — зафиксировать blocker.
- Dirty worktree пересекается с задачей и происхождение изменений неясно — не перезаписывать.
- Focused test красный, mutation не атомарна или false success возможен — не ставить `done` и не идти дальше.
- Production cutover запрещён до выполнения no-go условий из плана.
