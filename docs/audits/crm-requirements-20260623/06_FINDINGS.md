# Findings

### P1-01: Предметная модель не соответствует новой цели

- **Promise:** система управления магазином.
- **Reality:** схема и API обслуживают Telegram-лояльность.
- **Effect:** смены, склад и маркировки нельзя реализовать без новых сущностей.
- **Direction:** добавить CRM-модули на текущем стеке.
- **Status:** confirmed.

### P1-02: Frontend не связан с API

- **Promise:** рабочая административная панель.
- **Reality:** основные запросы отключены, страницы используют мок-данные.
- **Effect:** отображаемые данные не являются данными БД.
- **Direction:** подключать каждый новый экран к versioned API.
- **Status:** confirmed.

### P1-03: Нет рабочей авторизации и серверных ролей

- **Promise:** ролевой доступ.
- **Reality:** роль `owner` задана во frontend, middleware авторизации отсутствует.
- **Effect:** невозможно безопасно разграничить склад, персонал и настройки.
- **Direction:** реализовать авторизацию до бизнес-модулей.
- **Status:** confirmed.

### P2-01: Нет миграций и тестового контура

- **Effect:** изменения схемы и критическая логика остатков будут трудно проверяемыми.
- **Direction:** добавить миграции и интеграционные тесты на первом этапе.
- **Status:** confirmed.

### P2-02: Исходная документация конфликтует с текущим кодом

- **Reality:** документы описывают Telegram-лояльность и местами другой стек.
- **Effect:** их нельзя использовать как актуальное ТЗ для CRM.
- **Direction:** считать `docs/crm/` новым источником требований.
- **Status:** confirmed.
