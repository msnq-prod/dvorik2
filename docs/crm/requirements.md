# Требования к CRM магазина

## 1. Цель

Система должна дать владельцу магазина единое место для:

- планирования смен сотрудников;
- контроля товарных остатков;
- печати маркировок из карточек товаров.

## 2. Роли

| Роль | Права |
|---|---|
| Владелец | полный доступ, пользователи, настройки, аудит |
| Менеджер | сотрудники, смены, товары, склад, печать |
| Кладовщик | товары, складские движения, печать |
| Сотрудник | просмотр собственных смен |
| Наблюдатель | только просмотр разрешённых разделов |

Права должны проверяться backend-сервисом. Скрытие кнопок во frontend не считается защитой.

## 3. Функциональные требования

### 3.1. Авторизация и аудит

- `AUTH-01` — вход по логину и паролю.
- `AUTH-02` — безопасная серверная сессия.
- `AUTH-03` — разграничение доступа по ролям.
- `AUTH-04` — блокировка неактивного пользователя.
- `AUDIT-01` — журнал создания, изменения и удаления сотрудников, смен, товаров и складских движений.
- `AUDIT-02` — запись пользователя, времени, сущности и изменённых полей.

### 3.2. Сотрудники

- `EMP-01` — список сотрудников с поиском и фильтром по статусу.
- `EMP-02` — создание и редактирование карточки сотрудника.
- `EMP-03` — обязательные поля: ФИО, роль/должность, статус.
- `EMP-04` — дополнительные поля: телефон, email, комментарий, дата приёма.
- `EMP-05` — деактивация без физического удаления истории.
- `EMP-06` — просмотр будущих и завершённых смен сотрудника.

### 3.3. Смены

- `SHIFT-01` — календарь смен в режимах неделя и месяц.
- `SHIFT-02` — создание смены с датой, временем начала/окончания и торговой точкой.
- `SHIFT-03` — назначение одного или нескольких сотрудников.
- `SHIFT-04` — предупреждение о пересечении смен сотрудника.
- `SHIFT-05` — копирование смены или расписания на другой день/неделю.
- `SHIFT-06` — статусы: `draft`, `scheduled`, `in_progress`, `completed`, `cancelled`.
- `SHIFT-07` — комментарий менеджера к смене.
- `SHIFT-08` — сотрудник видит только собственное расписание, если у него нет расширенной роли.

### 3.4. Товары

- `PRODUCT-01` — каталог товаров с поиском, фильтрами и пагинацией.
- `PRODUCT-02` — карточка товара: название, SKU, штрихкод, категория, единица измерения, цена, статус.
- `PRODUCT-03` — SKU должен быть уникальным.
- `PRODUCT-04` — штрихкод должен быть уникальным, если указан.
- `PRODUCT-05` — поддержка товара без штрихкода с возможностью сгенерировать внутренний Code 128.
- `PRODUCT-06` — архивирование товара без удаления складской истории.
- `PRODUCT-07` — минимальный допустимый остаток для уведомления.

### 3.5. Склад

- `STOCK-01` — остаток показывается по товару и складу/торговой точке.
- `STOCK-02` — типы движений: приход, продажа/расход, списание, корректировка, перемещение.
- `STOCK-03` — каждое изменение остатка создаётся только через складское движение.
- `STOCK-04` — движение содержит количество, основание, автора и время.
- `STOCK-05` — отрицательный остаток запрещён по умолчанию.
- `STOCK-06` — перемещение между складами выполняется атомарно.
- `STOCK-07` — просмотр полной истории движений товара.
- `STOCK-08` — отдельный список товаров ниже минимального остатка.
- `STOCK-09` — массовая инвентаризационная корректировка с обязательным комментарием.

### 3.6. Маркировки

- `LABEL-01` — печать маркировки из карточки товара и из списка товаров.
- `LABEL-02` — массовый выбор товаров и количества этикеток.
- `LABEL-03` — выбор шаблона этикетки.
- `LABEL-04` — на этикетке поддерживаются: название, цена, SKU, штрихкод, дата печати.
- `LABEL-05` — предпросмотр перед печатью.
- `LABEL-06` — основной результат MVP — PDF, пригодный для печати из браузера.
- `LABEL-07` — поддержка Code 128; EAN-13 разрешён только для корректного 13-значного кода.
- `LABEL-08` — журнал заданий печати: пользователь, шаблон, товары, количество, время.
- `LABEL-09` — повторная печать предыдущего задания.
- `LABEL-10` — цена и данные товара фиксируются в задании печати, чтобы повторная печать была воспроизводимой.

### 3.7. Главная страница

- `DASH-01` — количество сотрудников на текущей смене.
- `DASH-02` — ближайшие смены.
- `DASH-03` — количество активных товаров.
- `DASH-04` — товары с низким или нулевым остатком.
- `DASH-05` — последние складские движения.

## 4. Нефункциональные требования

- `NFR-01` — интерфейс на русском языке.
- `NFR-02` — часовой пояс системы: `Asia/Vladivostok`.
- `NFR-03` — основные списки открываются не дольше 2 секунд при 10 000 товаров и 100 000 движений.
- `NFR-04` — пагинация выполняется на сервере; максимум 100 записей за запрос.
- `NFR-05` — все денежные значения хранятся как `numeric`, не `float`.
- `NFR-06` — все изменения остатков выполняются в транзакции.
- `NFR-07` — резервное копирование PostgreSQL минимум раз в сутки.
- `NFR-08` — критические операции имеют подтверждение и понятную ошибку.
- `NFR-09` — desktop-first интерфейс, рабочая адаптация для планшета.
- `NFR-10` — тесты покрывают расчёт остатков, пересечения смен и генерацию маркировок.

## 5. Критерии готовности MVP

MVP принят, если:

1. менеджер создаёт сотрудника и назначает его на смену;
2. система не позволяет незаметно назначить пересекающиеся смены;
3. кладовщик создаёт товар и проводит приход;
4. остаток совпадает с суммой подтверждённых движений;
5. отрицательный остаток блокируется;
6. пользователь выбирает товары, формирует PDF и печатает этикетки;
7. все операции доступны только разрешённым ролям и отражаются в аудите.

## 6. Решения, которые нужно подтвердить до разработки печати

1. Размеры этикеток.
2. Модели принтеров и формат бумаги: A4, рулон 58/80 мм или оба варианта.
3. Нужен ли российский Data Matrix/«Честный знак». Это отдельная интеграция и не равно обычному штрихкоду.
4. Сколько торговых точек и складов будет в первой версии.
5. Нужно ли сохранять текущий модуль лояльности в основном меню.
